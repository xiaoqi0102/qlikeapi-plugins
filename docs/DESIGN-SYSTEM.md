# UI 设计规范（DESIGN-SYSTEM）

> 这份文档是**规范性**的：控制台里新增页面、新增组件、改样式，都要按它来。
> 规范不是审美建议，而是把「用户否掉过的做法」和「踩过的坑」固化成可执行的约定。
>
> 在线预览：`http://<面板地址>/ui-kit`（登录后可见，页面上每个组件都能点）
> 代码位置：`app/static/css/tokens.css`（变量）+ `app/static/css/ui-kit.css`（组件）+ `app/static/js/ui-kit.js`（交互）

---

## 0. 改 UI 前先看这三句

1. **侧边导航栏不动**（保持左侧竖排、9 个入口）。只做视觉与交互升级。
2. **每个按钮都必须有真实用途** —— 点了没反应的按钮是硬伤，不算"占位"；同一动作不要在页头和工具栏各放一个。
3. **改完必须过验收四件套**（见 §9）：语法检查 → 部署 → 计算样式指纹比对 → 截图核对，且**全程零成本**（不许发带 prompt 的请求）。

## 1. 设计原则

| 原则 | 落地做法 |
|---|---|
| **信息密度优先** | 列表用紧凑表格（`.tb`），不用大卡片堆叠；一屏能看多少行就排多少行 |
| **状态一眼可见** | 状态用 `.pill` 四档色（ok/warn/err/info）+ 圆点；数值用 `.num` 等宽右对齐 |
| **操作就地完成** | 能在已有页面表达就不新建导航项；路由规则并进「渠道实例」页折叠面板就是这条的产物 |
| **少弹窗、弹窗必有用** | 弹窗只用于「新建/编辑表单」和「不可逆操作确认」；展示型信息放面板或吐司 |
| **加性改造** | 深色模式、组件库都是**纯加性**：旧类名保留，新组件用新前缀（`.pk-` / `.cf-`），随时可回退 |

## 2. 设计变量（唯一来源：`css/tokens.css`）

组件里**不许写死颜色/圆角/阴影**，一律用变量；深色模式只覆盖 `body.dark` 里的同名变量。

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--ink` | `#0f172a` | `#e8edf5` | 主文字 |
| `--ink-2` | `#334155` | `#c2cbd9` | 次级文字 |
| `--muted` | `#64748b` | `#8494a8` | 辅助说明（`.hint`） |
| `--line` / `--line-2` | `#e6ebf2` / `#eef1f6` | `#243044` / `#1e293b` | 边框 / 分隔线 |
| `--bg` | `#f5f7fb` | `#0d1421` | 页面底色 |
| `--brand` / `--brand-2` | `#2f6bff` / `#1d4ed8` | 同 | 主色（按钮、选中、链接） |
| `--ok` / `--warn` / `--err` | `#16a34a` / `#d97706` / `#dc2626` | 同 | 状态色 |
| `--*-soft` | 浅底 | 深底 | 徽章/图标底色 |
| `--r-xs/-sm/-r/-lg` | `6/9/12/16px` | 同 | 圆角 |
| `--sh-1/2/3` | 三级阴影 | 更深 | 卡片 / 悬浮 / 弹层 |
| `--ring` | 蓝色焦点环 | 同 | 输入聚焦 |
| `--mono` | 等宽字体栈 | 同 | key、路径、JSON |
| `--fs-xs…xl` / `--sp-1…5` / `--dur` | `11–18px` / `4–24px` / `.15s` | 同 | 新组件的字号/间距/动效刻度 |

> **新组件必须引用变量，禁止魔法数字。** 历史上沿用的小数字号（`11.5px` / `12.5px` / `13.5px`）暂时保留字面量——
> 它们不在刻度上，硬套变量会改变渲染值；收敛时按批次替换，每批都必须跑 `make ui-diff` 证明零差异。

## 3. 页面骨架

```
.layout
├── aside.side          固定侧栏 232px：品牌 → 9 项导航 → 底部主题切换
└── main                主区
    ├── .topbar         页面标题 + 说明 + 全局操作（主题、退出）
    └── section.v-*     每个视图一个 section，切换靠 hidden
        └── .grid2/.grid3/.cards   栅格（窄屏自动单栏）
            └── .panel     功能块：header(h3 + 右上角 .acts) + .body
```

- 一屏内的面板数控制在 2–4 个；面板之间统一 `mt-3`/`gap-14px` 节奏。
- 面板 = 一个自洽功能块：标题说"这是什么"，右上角放**该块**的主操作，内容只放表格/表单/图表之一。
- 表格页工具栏一行：搜索 + `.seg` 分段筛选（全部/启用/停用/异常）+ 计数 + 主操作 + 刷新。

## 4. 组件库清单

### 4.1 CSS 组件（`ui-kit.css`）

| 组件 | 类名 | 用途 / 禁忌 |
|---|---|---|
| 面板 | `.panel > header/.body` | 功能块容器；`header` 里放 `h3` + `.acts` |
| KPI 卡片 | `.stat`（`.ok/.warn/.err`） | 概览页顶部；`UI.stat(k,v,x,icon,tone)` |
| 表格 | `.table-wrap > table.tb` | 列表页统一用它；表头吸顶、行 hover |
| 徽章 | `.pill` + `ok/warn/err/info` + `dot` | **只**表达状态，不要自定义含义 |
| 标签 | `.chip` | 中性信息：类型、模型名、渠道 key |
| 按钮 | `.btn` 系列、`.ibtn`（图标按钮，**必须带 `title`**） | 危险操作用 `.btn-outline-danger` / `.ibtn.danger` |
| 操作列 | `.acts` | **横排**（inline-flex + 6px）。**禁止用 `.row`** —— Bootstrap 的 `.row>*` 宽度 100%，会把按钮挤成竖排 |
| 开关 | `.sw` | 表格右侧直接启停 |
| 密钥字段 | `.pinp` | 等宽 + 打码 + 眼睛按钮 |
| 分段筛选 | `.seg button.on` | 工具栏筛选 |
| 骨架屏 | `.sk` / `UI.skelTable` | 首屏加载；列宽与真实表格对齐，避免加载完跳动 |
| 空状态 | `.empty` | 虚线卡片 + 图标 + **一句"下一步点什么"** |
| 进度条 | `.bar` | 探活/批量任务进度 |
| 吐司 | `#toast .t`（`.err`） | 右下角 3.8s；`UI.toast(msg, bad)` |
| 弹窗 | `#modal` + Bootstrap Modal | `UI.modal(title, body, foot, onShown)` |
| 确认框 | `.cf` | `UI.confirm(msg, {okText})` → Promise；**禁止原生 `confirm()`** |
| **多选选择器** | `.pk-*` | `UI.picker()`，见 §4.3 |
| 工具类 | `.hint .mono .num .acts .grid2 .grid3` | 辅助文字 / 等宽 / 数字 / 操作横排 / 栅格 |

### 4.2 JS 组件（`ui-kit.js` → `window.UI`）

```
基础   UI.$  UI.$$  UI.esc  UI.fmtTime  UI.timeAgo  UI.fmtMs  UI.money  UI.cur  UI.copy
反馈   UI.busy(on)  UI.toast(msg,bad)  UI.modal(...)  UI.closeModal()  UI.confirm(msg,opts)
展示   UI.pill  UI.chip  UI.stat  UI.empty  UI.table  UI.skelTable  UI.bar(pct)
表单   UI.picker(host, opts)
```

铁律：**组件只做「渲染 + 交互」，不发请求、不碰业务**。业务逻辑一律留在 `app.js`。

### 4.3 多选选择器 `UI.picker`（凡是"从已有集合里挑若干个"都必须用它）

```js
UI.picker('#pkModels', {
  items: [{value, label, hint, group, disabled}],   // 候选集（来自后端，不要手写死）
  selected: ['gpt-image-2'],
  placeholder: '全部模型（不限）',                    // 空 = 不限 的语义要写在占位文案里
  search: true, maxChips: 2,
  onChange: (values) => {}
});
// 取值：state._pk = UI.picker(...); state._pk.values
```

- **不要用逗号分隔的文本框**：手输拼错模型名/渠道名看不出来，也选不出不存在的项。
- 候选集来自 `GET /api/meta/options`（模型 + 渠道 + 币种，只读、不打上游）。
- 必须挂在 `UI.modal(...)` 的第 4 个参数（`onShown`）里 —— 弹窗淡入前控件尺寸为 0，下拉定位会错位。

## 5. 交互与状态规范

| 场景 | 规范 |
|---|---|
| 加载中 | 首屏用骨架屏（`UI.skelTable`），局部刷新用按钮转圈 + 顶部 `.busy` 进度条；**不要**整页遮罩 |
| 空 | 空状态必须给下一步动作（「点右上角『新建令牌』…」），不要只写"暂无数据" |
| 失败 | 吐司写清原因（`失败：上游 402 余额不足`），不要只说"操作失败"；字段级错误写在字段下方 |
| 成功 | 短吐司即可；新建类操作要弹窗展示**唯一一次**明文（如令牌 key）+ 复制按钮 |
| 破坏性操作 | 必须 `UI.confirm` 二次确认，文案写清后果（「删除后调用会立刻 401」） |
| 批量操作 | 勾选后从上方滑出批量条；表头全选**只选当前筛选结果** |
| 耗时操作 | 弹窗内逐项一行：等待中 → 探测中 → ✓/✗ + 耗时 + 状态码；**顺序执行**，不并发打上游；用户中途关弹窗要能立刻停 |
| 危险动作 | 禁止把带 prompt 的请求发给真实上游（出图=扣费）；验证走本地 400 / `preview` dry-run |

---

## 6. 文案规范

- 按钮用**动词**：保存 / 创建并生成 key / 全部刷新 / 清零（不要"确定""提交"这种无信息量词）。
- 说明文字写"为什么"，不重复标签：`允许的模型 · 不选=全部` + 「从模型目录里勾选，避免手输拼错模型名」。
- 错误信息包含**可行动信息**：谁失败、为什么、怎么办。
- 币种分列显示、不做汇率换算（`$3.24 + ¥1.50`），并标注价格来源。

## 9. 变更流程（改 UI 必做，缺一不可）

```bash
node --check app/static/js/app.js          # 1. 语法
python3 -m pytest tests/ -q                # 2. 测试（含组件库/展示页用例）
docker compose up -d --build               # 3. 部署（静态文件打在镜像里，必须重建）
make ui-diff                               # 4. 新旧样式 A/B 逐元素比对 → 期望「合计差异: 0」
```

- **`make ui-diff`**（`scripts/ui_style_diff.py`）：把改动前的 `style.css` 放进容器，同一页面状态下
  切换新旧样式表，**逐元素比对计算样式**。CSS 靠书写顺序决胜，静态看代码看不出问题，只有让浏览器真算一遍才可靠。
  脚本只允许新组件（`.pk-*` / `.cf-*` 内部元素）出现差异，其余必须 0 差异。
- 再做**截图 + 视觉抽检**：浅色/深色各一张，重点看有没有白色亮块、黑底黑字、按钮竖排、图标缺失。
  能用 DOM 断言就别问视觉模型（它对渐变、图标宽度判断不可靠）：例如
  `document.fonts.check('16px tabler-icons')`、`getComputedStyle(i).fontFamily`。
- **零成本铁律**：验收只用只读 GET / 本地 400 / dry-run preview；带 prompt 的请求一律不发。

## 10. 坑清单（改一次会再犯的那种）

1. **操作列用 `.row` 会竖排** —— Bootstrap 5 的 `.row > *` 是 `width:100%`。操作按钮统一用 `.acts`。
2. **弹窗里挂选择器要在 `onShown`** —— 淡入前控件尺寸为 0，`getBoundingClientRect()` 全 0 → 下拉飞到左上角。
3. **深色模式救不回硬编码颜色** —— `background:#fff` 的选择器要逐个点名覆盖；**ID 优先级打不过**：`body.dark .t` 干不过 `#toast .t`，必须写 `body.dark #toast .t`。
4. **Chart.js v4 必须传 `<canvas>`** —— 传容器 `<div>` 会静默失败（图表区一片空白，页面其它正常）。图表颜色取自 CSS 变量 ⇒ 切换主题后必须重绘。
5. **剪贴板** —— 非 https/非 localhost 时 `navigator.clipboard` 不可用，必须回退 `execCommand`，否则复制按钮点了没反应（`UI.copy` 已封装）。
6. **静态文件路由要支持子目录** —— `/static/{path:path}` + `normpath` 前缀校验；用 `basename` 会让 `vendor/`、`css/`、`js/` 全 404。
7. **工具函数先 grep 再用** —— 用了不存在的 helper，`node --check` 查不出来。落笔前先看 `ui-kit.js` 有哪些 `UI.*`。
8. **`ok` 是三态** —— 渠道健康 `1/0/null`，别写 `h.ok === true`。
9. **前端字段取错会打成 500** —— 后端入参也要校验（非空字符串），违规返回 **400 + 人话**，不允许 500。
10. **图标宽度 0 ≠ 坏图标** —— 折叠容器（`details`、隐藏明细行）里的元素本来就没尺寸，先展开再判。
11. **CSS 别手滑** —— 写补丁后 grep 可疑字面量（`purple`、`#xxx`），无效值会让整条声明失效。
12. **测试定位器要唯一** —— `.modal >> text=保存` 会被提示文案里的"再保存"命中，用 `get_by_role("button", name="保存")`。
13. **合并重复 CSS 规则会翻转层叠顺序** —— 同优先级靠书写顺序决胜：把多条 `.btn` 合并到「最后出现位置」后，
    它会盖掉原本在它后面的 `.side-toggle{display:none}`，桌面端侧栏折叠按钮直接露出来（真踩过）。
    拆/合并样式表必须**保序**；加固一律用**提升特异性**，不要依赖书写顺序。
14. **公开截图必须脱敏** —— 面板里的掩码值（前 6 位…后 4 位，如内部主密钥）会随截图进公开仓库；
    截图脚本要在拍照前把匹配掩码的文本换成 `••••••••`（参考 `scripts/ui_style_diff.py` 同目录的脱敏写法）。
15. **HTML 属性里不能写 `\'`** —— `onclick="UI.toast(\'x\')"` 在 HTML 里是字面反斜杠，点了直接语法报错（真踩过，6 处）。

## 11. 组件展示页

`GET /ui-kit`（登录后可访问，与首页同一道门）：把上面每个组件都渲染一遍，**交互全部是真的**
（点吐司就弹吐司、点确认框就走 `UI.confirm`、点加载态就真的走骨架屏→数据），
并附可复制的用法片段。新增组件时**同步更新展示页**，否则规范会失真。

入口：控制台 →「设置」→「界面规范与组件库」→ 打开组件展示页 / 查看设计规范。

### 登录页（`css/login.css`）

登录页是**独立页面**，不加载控制台的 `tokens.css` / `ui-kit.css`，自带 `lg-*` 命名空间与青绿主色（视觉参照 Sub2API 登录页）：

| 类 | 用途 |
|---|---|
| `.lg-body` / `.lg-wrap` | 页面底色（青绿渐变 + 方格纹理）与居中容器 |
| `.lg-brand` / `.lg-mark` / `.lg-name` / `.lg-tag` | 品牌区（图标与 `favicon.svg` 同源） |
| `.lg-card` / `.lg-field` / `.lg-input` / `.lg-eye` | 卡片与表单（含密码可见性切换按钮） |
| `.lg-btn` / `.lg-msg` / `.lg-foot` | 主按钮 / 提示行 / 版权行 |

> 改登录页请只动 `login.css`；不要在 `tokens.css` 里加登录页专用变量，也不要把青绿主色带进控制台。
